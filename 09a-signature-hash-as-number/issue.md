# `read` stores the `[SIGNATURE]` hash as a `double` when the hex digest is a finite number

https://github.com/pulseq/pulseq/blob/c7469123c2f381f065986e6cc3a7d09730ed16ef/matlab/%2Bmr/%40Sequence/read.m#L85-L93

https://github.com/pulseq/pulseq/blob/c7469123c2f381f065986e6cc3a7d09730ed16ef/matlab/%2Bmr/%40Sequence/read.m#L452-L469

`read` reads the `[SIGNATURE]` section with `readDefinitions`, the reader of
`[DEFINITIONS]`. `readDefinitions` converts each value with `str2double`, and keeps the
text only when the number is not finite. An MD5 hex digest is text, but some digests are
also finite numbers: 32 decimal digits, or decimal digits with one `e` near the end (for
example `12345678901234567890123456789e12`). About 1 in 2,800,000 digests is one of
these. For such a file, `signatureValue` is a rounded `double`, not the hash, so it
cannot be compared with the hash that `write` gave, with the file, or with another file.

Below is a short demo

```matlab
% read stores the [SIGNATURE] hash as a double when the hex digest is a finite number.

% The value of 'Nonce' gives a file whose MD5 digest has only decimal digits. It was
% found by trying 'n-0', 'n-1', and so on. write signs the file itself, so the hash is
% correct for the file.
seq = mr.Sequence();
seq.addBlock(mr.makeDelay(1e-3));
seq.setDefinition('Nonce', 'n-8829771');

fn = [tempname() '.seq'];
seq.write(fn);
fprintf('after write: signatureValue = ''%s'' (%s)\n', seq.signatureValue, class(seq.signatureValue));

seq2 = mr.Sequence();
seq2.read(fn);
fprintf('after read:  signatureValue = %.17g (%s)\n', seq2.signatureValue, class(seq2.signatureValue));
delete(fn);

fprintf('isequal(signatureValue): %d (expected: 1)\n', isequal(seq.signatureValue, seq2.signatureValue));
```

which outputs

```
after write: signatureValue = '65729202117365480580180366844819' (char)
after read:  signatureValue = 6.5729202117365483e+31 (double)
isequal(signatureValue): 0 (expected: 1)
```

If the `[SIGNATURE]` branch kept the values as text, for example with
`strtrim(line((length(key)+2):end))` for each line in place of `str2double`, then
`signatureValue` would be the text of the `Hash` line for each digest. `[DEFINITIONS]`
would not change.
