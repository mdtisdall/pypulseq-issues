# `write()` fails with `KeyError` after `read()` of a file older than 1.5 with RF events

**Describe the bug**

After `read()` of a Pulseq file older than 1.5.0 that has an RF event, `write()` fails
with `KeyError` on the ID of the first RF event. So pypulseq cannot save (for example,
convert to 1.5) a 1.2, 1.3 or 1.4 file that it has read. `get_block()` and the waveforms
work; only `write()` fails.

**To Reproduce**

The bug is in a 1.4.1 file of one block with one RF block pulse. A 1.4 `[RF]` row has 8
fields: no `center` and no `use`.

```python
import tempfile
from pathlib import Path

import pypulseq as pp

SEQ_1_4_1 = """\
[VERSION]
major 1
minor 4
revision 1

[DEFINITIONS]
AdcRasterTime 1e-07
BlockDurationRaster 1e-05
GradientRasterTime 1e-05
RadiofrequencyRasterTime 1e-06

# NUM DUR RF GX GY GZ ADC EXT
[BLOCKS]
1 20 1 0 0 0 0 0

# id amp mag_id phase_id time_id delay freq phase
[RF]
1 1000 1 2 0 0 0 0

[SHAPES]

shape_id 1
num_samples 100
1
0
0
97

shape_id 2
num_samples 100
0
0
98

"""

with tempfile.TemporaryDirectory() as tmp:
    path_in = Path(tmp) / 'rf_v141.seq'
    path_in.write_text(SEQ_1_4_1)

    seq = pp.Sequence()
    seq.read(str(path_in))
    print('rf_library.type after read():', dict(seq.rf_library.type))
    print('use of the RF event:', seq.get_block(1).rf.use)

    try:
        seq.write(str(Path(tmp) / 'out.seq'))
        rf_rows = (Path(tmp) / 'out.seq').read_text().split('[RF]\n')[1].splitlines()
        print('write(): ok, [RF] row:', ' '.join(rf_rows[0].split()))
    except KeyError as err:
        print('write():', repr(err))
```

Output (1.5.0.post1 and master):

```
rf_library.type after read(): {}
use of the RF event: undefined
write(): KeyError(1)
```

pypulseq's own test files fail the same way: `read()` then `write()` of each of
`tests/expected_output/simple_mprage120.seq`, `130`, `131`, `140`, `141` and `142` raises
`KeyError: 1`.

**Expected behavior**

`write()` works, and writes the RF event as a 1.5 row with the computed center and the use
`u`, as MATLAB Pulseq does for the same file:

```
1 1000 1 2 0 50 0 0 0 0 0 u
```

**Desktop (please complete the following information):**
 - OS: macOS
 - OS Version: 26.6.2
 - `pypulseq` version: 1.5.0.post1, and master at c977214 (2026-10-12). The code is the
   same in both.
 - Python 3.14.7, NumPy 2.5.4.
 - For comparison: MATLAB Pulseq (`pulseq/pulseq`) at c746912, run in GNU Octave 11.3.0.

**Additional context**

This bug was identified and test case generated by Claude, but I've reviewed the code
myself and the error appears to be a correct finding based on my review.

The `EventLibrary` of the RF events holds the numbers of each event in `data[id]` and its
use letter in a separate dict, `type[id]`. For a file older than 1.5:

1. The `[RF]` rows have no use column
   ([`read_seq.py`, lines 152-157](https://github.com/pulseq/pypulseq/blob/c977214ff439c0adf94d0e1ef8af44949f215e9b/src/pypulseq/Sequence/read_seq.py#L152-L157)),
   so `read()` stores the numbers and leaves `rf_library.type` empty.
2. The port to 1.5 means to give every RF event the use `'u'`, but builds the dict from
   the keys of `type`, which is empty, not from the keys of `data`
   ([line 326](https://github.com/pulseq/pypulseq/blob/c977214ff439c0adf94d0e1ef8af44949f215e9b/src/pypulseq/Sequence/read_seq.py#L326);
   the same at [line 262](https://github.com/pulseq/pypulseq/blob/c977214ff439c0adf94d0e1ef8af44949f215e9b/src/pypulseq/Sequence/read_seq.py#L262)
   for files older than 1.4):

   ```python
   self.rf_library.type = dict.fromkeys(self.rf_library.type.keys(), 'u')
   ```

3. It then calls `rf_library.update(i, None, (..., 'u'))`
   ([lines 333-337](https://github.com/pulseq/pypulseq/blob/c977214ff439c0adf94d0e1ef8af44949f215e9b/src/pypulseq/Sequence/read_seq.py#L333-L337)),
   which puts `'u'` at the end of the numbers instead of passing it as the type, and
   `EventLibrary.insert` sets `type[id]` only when a type is passed
   ([`event_lib.py`, lines 164-165](https://github.com/pulseq/pypulseq/blob/c977214ff439c0adf94d0e1ef8af44949f215e9b/src/pypulseq/event_lib.py#L164-L165)).
   With `read(..., remove_duplicates=False)` the stray `'u'` shows as an 11th element of
   `rf_library.data[1]`; the default `read()` drops it when it rounds the events.
4. `write()` writes the use as `self.rf_library.type[k]`
   ([`write_seq.py`, line 118](https://github.com/pulseq/pypulseq/blob/c977214ff439c0adf94d0e1ef8af44949f215e9b/src/pypulseq/Sequence/write_seq.py#L118)),
   and there is no entry for the event.

*Suggested fix*

In both ports (lines 262 and 326), build the types from the keys of `data`, and pass
`'u'` to `update` as the type, not as a value:

```diff
-        self.rf_library.type = dict.fromkeys(self.rf_library.type.keys(), 'u')
+        self.rf_library.type = dict.fromkeys(self.rf_library.data.keys(), 'u')
 ...
-                (*d[:4], center, d[4], np.float64(0), np.float64(0), *d[5:7], 'u'),
+                (*d[:4], center, d[4], np.float64(0), np.float64(0), *d[5:7]),
+                'u',
```

With this change the example prints `rf_library.type after read(): {1: 'u'}` and
`write(): ok, [RF] row: 1 1000 1 2 0 50 0 0 0 0 0 u`, and the six `simple_mprage1xx.seq`
files are written and read back with 390 blocks each. `fix.diff` also extends
`test_sequence_backwards_compatibility` to write each ported sequence; the extended test
fails without the fix (6 failed) and passes with it (6 passed). The pypulseq test suite
gives the same result with and without the change (1268 passed, 24 skipped, serial run;
the 2 tests of `test_sigpy.py` fail in both, as the optional `sigpy` is not installed).
