# `signatureValue` is kept after `addBlock`, and after `read` of a file with no `[SIGNATURE]`

https://github.com/pulseq/pulseq/blob/c7469123c2f381f065986e6cc3a7d09730ed16ef/matlab/%2Bmr/%40Sequence/read.m#L29-L43

https://github.com/pulseq/pulseq/blob/c7469123c2f381f065986e6cc3a7d09730ed16ef/matlab/%2Bmr/%40Sequence/readBinary.m#L46-L52

`readBinary` sets `signatureType`, `signatureFile` and `signatureValue` to `''` before it
reads a file. `read` makes new event libraries and a new block table, but it does not
reset the signature fields, and it sets them only when the file has a `[SIGNATURE]`
section. So when a file with no `[SIGNATURE]` section is read into a `Sequence` that read
a signed file before, `signatureValue` is the hash of the earlier file.

In the same way, `addBlock` and `setBlock` do not change the signature fields. After a
block is added, `signatureValue` is still the hash of the file that `write` or `read`
handled, although the sequence no longer matches that file.

Below is a short demo

```matlab
% Sequence keeps the [SIGNATURE] hash after addBlock, and after read of a file with no
% [SIGNATURE] section.

signed_fn = [tempname() '.seq'];
unsigned_fn = [tempname() '.seq'];

seq = mr.Sequence();
seq.addBlock(mr.makeTrapezoid('x', 'Area', 1000, 'Duration', 2e-3));
seq.write(signed_fn);
fprintf('after write:                       signatureValue = ''%s''\n', seq.signatureValue);

seq.addBlock(mr.makeDelay(1e-3));
fprintf('after addBlock:                    signatureValue = ''%s''\n', seq.signatureValue);

seq.write(unsigned_fn, false);  % no [SIGNATURE] section

seq2 = mr.Sequence();
seq2.read(signed_fn);
seq2.read(unsigned_fn);
fprintf('signed, then unsigned file read:   signatureValue = ''%s''\n', seq2.signatureValue);

seq3 = mr.Sequence();
seq3.read(unsigned_fn);
fprintf('unsigned file into a new Sequence: signatureValue = ''%s''\n', seq3.signatureValue);

delete(signed_fn);
delete(unsigned_fn);
```

which outputs

```
after write:                       signatureValue = 'aef88647c63d540133dcff5555a5f371'
after addBlock:                    signatureValue = 'aef88647c63d540133dcff5555a5f371'
signed, then unsigned file read:   signatureValue = 'aef88647c63d540133dcff5555a5f371'
unsigned file into a new Sequence: signatureValue = ''
```

The last three values would be `''`, as for a new `Sequence`, if `read` set the three
fields to `''` next to the new event libraries, as `readBinary` does, and `setBlock`
(which `addBlock` calls) set them to `''` as well.

Versions: MATLAB Pulseq (`pulseq/pulseq`) master at c746912 (2026-09-17), run in GNU
Octave 11.3.0.
