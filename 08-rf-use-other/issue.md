# add_block stores an RF event with use='other' as undefined

**Describe the bug**

`'other'` is one of the supported RF uses (`get_supported_rf_uses()`), and the `make_*`
RF functions accept `use='other'`. But when such a pulse is added to a sequence,
`register_rf_event` stores its use as `'u'` (undefined), not `'o'`. Its list of uses
has five entries: `'other'` is missing. So `get_block` returns `use='undefined'` for
that pulse, and `write` writes `u` to the `.seq` file, so the use is also lost after a
write and a read.

The reader already maps the letter `o` back to `'other'`
([`Sequence/sequence.py`, lines 1287-1295](https://github.com/pulseq/pypulseq/blob/f2c582bae13145b8ac71958726bc8b5a14bd1cfd/src/pypulseq/Sequence/sequence.py#L1287-L1295)),
and MATLAB Pulseq stores `'other'` as `o`.

**To Reproduce**

```python
import os
import tempfile

import numpy as np
import pypulseq as pp

system = pp.Opts()

# 'other' is one of the supported uses, so make_block_pulse accepts it.
print('supported uses:', pp.supported_labels_rf_use.get_supported_rf_uses())
rf = pp.make_block_pulse(np.pi / 2, duration=1e-3, use='other', system=system)
print('event use:', rf.use)  # other

seq = pp.Sequence(system)
seq.add_block(rf)

# The RF library keeps the use as one letter.
print('library letter:', seq.rf_library.type[1], '(expected: o)')
print('get_block use:', seq.get_block(1).rf.use, '(expected: other)')

# The letter is written to the .seq file, so the use is lost there too.
with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, 'other.seq')
    seq.write(path)
    read_back = pp.Sequence(system)
    read_back.read(path)
    print('after write and read:', read_back.get_block(1).rf.use, '(expected: other)')
```

Output:

```
supported uses: ('excitation', 'refocusing', 'inversion', 'saturation', 'preparation', 'other', 'undefined')
event use: other
library letter: u (expected: o)
get_block use: undefined (expected: other)
after write and read: undefined (expected: other)
```

**Expected behavior**

The library letter `o`, and `use='other'` from `get_block` and after a write and a read.

MATLAB Pulseq keeps it:
[`registerRfEvent` in `Sequence.m`](https://github.com/pulseq/pulseq/blob/c746912/matlab/%2Bmr/%40Sequence/Sequence.m#L617-L627)
has `case {'excitation','refocusing','inversion','saturation','preparation','other'}`
and stores `event.use(1)`.

**Suggested fix**

[`Sequence/block.py`, lines 868-879](https://github.com/pulseq/pypulseq/blob/f2c582bae13145b8ac71958726bc8b5a14bd1cfd/src/pypulseq/Sequence/block.py#L868-L879):
test the use against `get_supported_rf_uses()` instead of a list of its own. The first
letter of each supported use is its letter in the file (`'u'` for `'undefined'`), so
the list and the reader cannot drift apart again. `fix.diff` has this change; with it,
the example prints `o` and `other` three times, and the pypulseq test suite passes
(1264 passed, 24 skipped, serial run; the same without the change).
