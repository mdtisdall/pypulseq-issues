# `read` sets `signature_file` to `'Text'`, but `write` sets `'text'`

**Describe the bug**

After `write`, `Sequence.signature_file` is `'text'`
([`Sequence/sequence.py`, line 1867](https://github.com/pulseq/pypulseq/blob/f2c582bae13145b8ac71958726bc8b5a14bd1cfd/src/pypulseq/Sequence/sequence.py#L1867)).
After `read` of the same file, it is `'Text'`
([`Sequence/read_seq.py`, line 100](https://github.com/pulseq/pypulseq/blob/f2c582bae13145b8ac71958726bc8b5a14bd1cfd/src/pypulseq/Sequence/read_seq.py#L100)).
So a check such as `seq.signature_file == 'text'` is false after `read`.

pypulseq follows MATLAB Pulseq here, which has the same `'Text'` in `read.m`, while its
`Sequence.m` documents `'text'` or `'bin'`. I reported that as pulseq/pulseq#XXX.

**To Reproduce**

```python
import os
import tempfile

import pypulseq as pp

seq = pp.Sequence()
seq.add_block(pp.make_delay(1e-3))

fd, fn = tempfile.mkstemp(suffix='.seq')
os.close(fd)
seq.write(fn)
print(f"after write: signature_file = '{seq.signature_file}'")

seq2 = pp.Sequence()
seq2.read(fn)
print(f"after read:  signature_file = '{seq2.signature_file}'")
os.remove(fn)

print(
    f"signature_file == 'text': {seq.signature_file == 'text'} after write, "
    f"{seq2.signature_file == 'text'} after read"
)
```

Output:

```
after write: signature_file = 'text'
after read:  signature_file = 'Text'
signature_file == 'text': True after write, False after read
```

**Expected behavior**

`'text'` after `write` and after `read`, as in the fix proposed in pulseq/pulseq#XXX.

**Suggested fix**

```diff
             if 'Hash' in temp_sign_defs:
                 self.signature_value = temp_sign_defs['Hash']
-                self.signature_file = 'Text'
+                self.signature_file = 'text'
```

With this change, the example prints `'text'` twice. #402 had the same change, among
larger ones (binary signatures), but was closed without merge.

I will open a PR with this fix and a regression test.
